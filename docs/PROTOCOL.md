# Cachito ID 36 驱动依据

目标型号是 Cachito「诱桃·偷欢 Pro AI版」，协议 ID 36。该实现来源于对 Cachito 2.7.7 控制逻辑的分析和既有手机广播日志核对；旧定制宿主中的编码与角色控制已有设备持有人实测。本次独立桥接版本的手机端验证仍待完成。

此设备不使用 GATT 建连。手机发送不可连接、不可扫描的 legacy BLE 广播，将一条 16 字节指令作为 128 位 Service UUID。控制端不扫描设备，不使用蓝牙名称作为识别依据。

## 格式

强度模板（不含最终校验字节）：`71000C{命令序号}8200{控制端编号}0100640000{强度编码}02`

停止模板（不含最终校验字节）：`71000C{命令序号}0F00{控制端编号}01000000000000`

- 命令序号：100–255 的随机字节。
- 控制端编号：每次独立安装生成的随机 2 字节编号；不是用户的蓝牙地址。
- 强度编码：`floor(power * 0.5 + 50)`，有效 power 为 2–100；0–1 走停止帧。
- 校验：前 15 字节求和后取低 8 位。
- 广播：legacy、interval 160、high TX、不含设备名称。

公开测试使用虚构的 `BEEF` 控制端编号，按已确认的格式重新计算样例。不分发用户的原始日志或实际控制端编号。

## 能力边界

本驱动只实现已确认的执行通道，不生成温度或其他型号的指令。波浪/脉冲由上层连续改变强度实现，网页计时器暂停时节奏也可能暂停。

协议没有设备回执或已确认的按蓝牙地址定向机制，不能将“广播已发送”称为“玩具已连接/已动作”。附近若有多台接受相同协议的设备，存在同时响应的可能；配对密钥只认证酒馆与本机设备桥，不是玩具硬件配对。

增加新型号必须取得相应协议依据，并分别验证启动、强度范围、停止、异常路径与实体设备表现；不能只根据蓝牙名称复用此驱动。
